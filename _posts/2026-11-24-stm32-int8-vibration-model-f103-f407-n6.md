实验室角落那台小风机最近总在半夜异响，我拿一块 STM32F103C8 最小系统板加 MPU6050 做了个监测节点：三轴加速度按 1 kHz 采样，串口把原始波形全部发给上位机，再由 Python 脚本画频谱。板子跑得很稳，问题出在链路上——上位机一关，数据就断；线拉长一点，串口开始丢字节；想放到另一台设备旁边，又得再搬一台电脑。

于是很自然冒出个念头：能不能让板子自己判断正不正常，只把结论和少量波形传出来。正好 11 月 4 日 ST 在峰会上把 STM32 收拢成一个统一平台，新增的 STM32A 系列往功能安全和汽车走，带 Neural-ART NPU 的 STM32N6 也被反复提及。新闻看完，我关心的不是产品线怎么排，而是三个具体问题：这个模型到底多大、M3 上怎么写才不慢、换芯片时哪些代码能留下。

## 一、先把模型拆成能算的数

异常检测不需要很深的网络。我用的是一个很小的三通道一维卷积：输入三轴各 256 个点，第一层 8 个通道、卷积核 5、步长 1，第二层 16 个通道、卷积核 5、步长 2，接全局最大池化，最后一个 16 进 2 的全连接输出「正常/异常」。训练在上位机做，部署前统一量化成 int8。

乘加次数是可以手算的，不需要上板才知道：

| 层 | 输入 → 输出 | 乘加次数 | 参数量 |
|---|---|---|---|
| Conv1d 1 | 3×256 → 8×252 | 252×8×15 = 30,240 | 128 |
| Conv1d 2 | 8×252 → 16×124 | 124×16×40 = 79,360 | 656 |
| 全连接 | 16 → 2 | 32 | 34 |
| 合计 | — | 约 11 万 | 818 |

权重加偏置不到 1 KB（偏置用 int32 也就 3 KB 出头），激活峰值是两层卷积输出里较大的那组，输入 768 B 加第一层输出 2016 B，再留一点余量，4 KB 够用。F103C8 只有 20 KB SRAM、64 KB Flash，但装这个模型绰绰有余。

这张表直接改变了我对「AI MCU」的判断。新闻里 NPU 的算力很唬人，可我这个模型只有十万次乘加的规模，瓶颈根本不在算力，而在采样、缓存和代码怎么组织。

## 二、M3 上没有 FPU 和 DSP，int8 内核只能自己写

F103 是 Cortex-M3，没有硬件浮点，也没有 M4 那套 SIMD/DSP 指令。CMSIS-NN 在这类内核上会回退到纯 C 路径，能跑，但占不到便宜。既然模型小，我干脆把推理写成不依赖任何库的定点卷积，编译选项只要 C99。

几个决定都是有原因的：

- **用 int8 而不是 float**：同样一份权重，int8 只占四分之一空间；M3 上 float 乘加要靠软件模拟，一条指令能做完的事会被拆成十几条。
- **累加用 int32**：单次乘积最大 255×127，一层最多 15 个输入通道乘 5 个抽头，累计不到 50 万，int32 完全放得下，不会溢出。
- **输入和权重都减零点**：量化后的 0 并不代表数值 0，不减零点等于给每个乘积加了一个常数偏置。权重用对称量化，零点恒为 0，所以代码里只减输入的零点。
- **再量化放到最后一次性做**：中间结果保持 int32，避免每层反复饱和丢精度；最后用 Q31 乘子加右移，把累加值映射回 int8。

scale 的取法也值得说一句。我用一批标定样本跑前向，统计每层激活的最大绝对值，除以 127 得到该层 scale；权重按输出通道分别统计，所以量化误差只影响单个卷积核，不至于一个离群值把整层精度拉垮。标定集里正常和异常样本都放，但必须和验证集分开，否则等于提前把答案喂给了量化器，板端精度会虚高。

```c
#include <stdint.h>

typedef struct {
    int32_t mult;    /* Q31 乘子 */
    int8_t  shift;   /* 再量化右移位数，>= 0 */
    int32_t zp_out;  /* 输出零点 */
} requant_t;

static inline int8_t sat_i8(int32_t v) {
    if (v > 127)  return 127;
    if (v < -128) return -128;
    return (int8_t)v;
}

/* 无 padding、stride=1 的一维卷积；权重按 [out_ch][in_ch][k] 排列 */
void conv1d_s8(const int8_t *in, int in_len, int in_ch, int32_t in_zp,
               const int8_t *w, const int32_t *bias,
               int out_ch, int k, const requant_t *rq,
               int8_t *out, int out_len)
{
    for (int oc = 0; oc < out_ch; ++oc) {
        int32_t b = bias ? bias[oc] : 0;
        for (int i = 0; i < out_len; ++i) {
            int32_t acc = b;
            for (int ic = 0; ic < in_ch; ++ic) {
                const int8_t *p = in + ic * in_len + i;
                const int8_t *q = w + (oc * in_ch + ic) * k;
                for (int j = 0; j < k; ++j)
                    acc += (int32_t)(p[j] - in_zp) * (int32_t)q[j];
            }
            int64_t t = (int64_t)acc * rq[oc].mult;
            t += (int64_t)1 << (30 + rq[oc].shift);      /* 四舍五入 */
            int32_t v = (int32_t)(t >> (31 + rq[oc].shift));
            out[oc * out_len + i] = sat_i8(v + rq[oc].zp_out);
        }
    }
}
```

`mult` 和 `shift` 不是拍脑袋填的，上位机量化时按输入、权重、输出三个 scale 算出来，再随权重一起导出。把乘子规整到 [0.5, 1) 区间，是为了让 Q31 乘子落在 int32 能表示的范围里：

```python
def requant_params(s_in, s_w, s_out, zp_out):
    real = s_in * s_w / s_out
    shift = 0
    while real < 0.5:              # 规整到 [0.5, 1)
        real *= 2.0
        shift += 1
    assert real < 1.0, "要求 s_in*s_w < s_out"
    mult = min(int(round(real * (1 << 31))), (1 << 31) - 1)
    return mult, shift, zp_out
```

按每个乘加摊到 8 条指令、72 MHz 主频粗算，11 万次乘加大约十几毫秒。每秒判断一次，这点开销不值一提——真正占时间的是 1 kHz 采样和 DMA 搬运，推理排在它们后面就行。这也解释了为什么我没有急着换板子：先把算力账算清楚，比看主频数字有用。

## 三、F407 和 N6 什么时候才值得上

手里还有一块 F407 探索板和一块 N6 开发板，我都试过把同一个模型搬过去，感受完全不同。

F407 是 Cortex-M4F，有单精度浮点和 DSP 指令，CMSIS-NN 的定点卷积能用到带累加的乘加指令，同样的内核不用改逻辑就有明显余量，浮点滤波也可以直接写。代价是时钟树、DMA 请求映射、串口引脚全要重配，BSP 得重写一遍。

上面那些指令数只是估算，上板后我用 Cortex-M3 自带的 DWT 周期计数器做了核对：推理前记下 CYCCNT，跑完再读一次，差值就是真实周期数，除以主频得到耗时。这个方法不占外设、不用示波器，比在中断里翻转 GPIO 再用逻辑分析仪量更直接。核对下来估算和实测在同一量级，方向没错，也就没必要再为几毫秒去做更复杂的优化。

H7 这类 M7 增加了数据缓存，DMA 写进内存的采样数据如果不在推理前清缓存，CPU 读到的可能是旧值。这个坑我在别的项目里踩过，必须做 32 字节对齐，再用地址范围清缓存，不能图省事整片清。

N6 的卖点是 Cortex-M55 加 Neural-ART NPU。但 NPU 擅长的是卷积层堆得足够多、参数量上来的模型；我这个十万次乘加的网络，光是图构建、张量搬运和调度开销就未必比纯 C 内核便宜。模型没长到百万次乘加、也没做图像或音频，上 NPU 属于用大炮打蚊子。

| 平台 | 内核 | 浮点/DSP | 加速器 | 对这个模型 | 主要迁移成本 |
|---|---|---|---|---|---|
| STM32F103C8 | Cortex-M3 72 MHz | 无 | 无 | 够用，已跑通 | 无，现有板 |
| STM32F407 | Cortex-M4F 168 MHz | 有 | 无 | 余量充足 | 重写 BSP、时钟、DMA |
| STM32H743 | Cortex-M7 480 MHz | 有 | 数据缓存 | 明显过设计 | 缓存一致性处理 |
| STM32N6570 | Cortex-M55 800 MHz | 有 | Neural-ART NPU | 小模型用不上 | 工具链、图部署 |

表里的「对这个模型」是经验判断，不是跑分。判断依据就是第一节那张乘加表：先用模型规模圈定候选，再看外设和成本。

## 四、统一平台真正省下的是什么

峰会上讲的统一平台，落点是架构、IP、软件和工具的复用：Cortex-M 内核加共通的设计原则，STM32Cube 生态保持一致，制程上 40 nm Flash 和 18 nm FD-SOI 带嵌入式相变存储作为后续基础。首批 STM32A4/A5/A9 已经给客户送样，计划 2027 年扩大供应。

这三个系列面向的是安全关键和车规场景，我手上这块小板子用不上。但它说明平台在往功能安全、资质认证和长期供货上走，对实验室那些要连续跑几年的设备反而是好消息——将来换系列时，至少不用把工具链和工程模板重学一遍。

但「统一」不等于引脚兼容，也不等于 DMA 配置能照抄。我的做法是把应用层和平台层的边界写死在一个能力头文件里，应用代码只问「有没有浮点、有没有缓存、SRAM 多大」，不直接判断型号：

```c
/* platform_caps.h：应用层只认能力，不认型号 */
#if defined(STM32F1)
#  define PLAT_SRAM_KB     20
#  define PLAT_HAS_FPU     0
#  define PLAT_HAS_DSP     0
#  define PLAT_HAS_DCACHE  0
#elif defined(STM32F4)
#  define PLAT_SRAM_KB     192
#  define PLAT_HAS_FPU     1
#  define PLAT_HAS_DSP     1
#  define PLAT_HAS_DCACHE  0
#elif defined(STM32H7)
#  define PLAT_SRAM_KB     1024
#  define PLAT_HAS_FPU     1
#  define PLAT_HAS_DSP     1
#  define PLAT_HAS_DCACHE  1
#else
#  error "未适配的平台：先写清能力和限制"
#endif
```

有了这层，特征窗口长度、量化参数、推理内核、阈值状态机、串口帧格式都能原样带走；必须重写的只剩采样触发配置、缓存维护、引脚映射和低功耗策略。这四类东西恰好是统一平台不会替你决定的部分，因为它们是板级事实。

## 五、我的选择

短期我留在 F103：模型小、板子现成、现场一秒判一次完全够，先把「板上判断 + 只传异常片段」跑稳。等特征从波形扩到频谱、模型涨到百万次乘加，再迁到 F407；如果以后要做声学或图像，才考虑 N6 那类带 NPU 的芯片。判据很简单：先算模型，再看外设，最后才看主频和 NPU 的数字。

这次算账最大的收获不是选了哪颗芯片，而是把「AI MCU」从新闻里拉回到自己的板子上。统一平台降低了以后迁移的软件成本，但板级差异永远存在，能力头文件比型号宏更经得起换芯。
